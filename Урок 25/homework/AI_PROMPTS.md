## 1. Code review

### 1.1. Вибір в'юх

```text
Ти — senior Django-розробник. Проєкт — книжковий магазин (Django 6.1,
застосунки shop, cart, orders, users; оплата Stripe Checkout + webhook).
Переглянь усі views і назви 3 найскладніші для code review: де найбільше
логіки, транзакцій, роботи з грошима чи зовнішніми сервісами.
Для кожної — одне речення, чому саме вона.
```

### 1.2. Рев'ю однієї в'юхи (повторювався для кожної з трьох)

```text
Зроби code review функції order_create з orders/views.py.

Контекст: Django 6.1, у продакшні PostgreSQL (docker-compose), у тестах
SQLite. Cart — кошик у сесії (cart/cart.py). Замовлення може оформити
і гість, і авторизований користувач.

Шукай по черзі:
1. помилки, що дають 500 або неправильні дані;
2. безпеку (доступ до чужих даних, IDOR, CSRF);
3. конкурентність і транзакції (select_for_update, deadlock);
4. зайві запити до бази (N+1).

Обмеження: не переписуй код «під себе», не міняй URL і назви шаблонів,
не додавай нових залежностей. Стиль і якість тексту не чіпай.

Формат: таблиця «проблема → чому це проблема → як виправити».
Для кожного пункту оціни, наскільки він критичний.
```

застосовувати. Окремо: чи справді потрібен @csrf_exempt на вебхуку Stripe?

## 2. Генерація тестів

```text
Ти — QA-інженер на Django. Згенеруй pytest-тести для моделей
Category, Book (shop/models.py), Order і OrderItem (orders/models.py).

Використовуй те, що вже є в проєкті: pytest-django,
фабрики з shop/tests/factories.py (factory-boy).

Перевір бізнес-логіку, а не Django:
- __str__, get_absolute_url, get_total_cost, get_cost;
- значення за замовчуванням;
- on_delete: CASCADE / PROTECT / SET_NULL;
- unique для slug, ordering для Order.

Кожен тест — окрема функція з короткою назвою.
Першим рядком у кожному тесті додай коментар:
# Generated with AI, reviewed and modified
```

```text
Запусти тести з покриттям для моделей:
pytest --cov=shop --cov=orders --cov=cart --cov=users
Мета — coverage ≥ 60 % для моделей. Покажи, які рядки не покриті.
```

**Що перевірено і змінено після генерації:**

- гроші порівнюються лише як `Decimal` (`Decimal("999.50")`), без `float`;
- у тесті `ordering` старому замовленню зсунуто `created_at` на добу назад:
  два записи, створені майже одночасно, можуть мати однаковий час, і тоді
  порядок нестабільний;
- тест `test_deleted_book` (рекомендація з рев'ю) спершу очікував редирект
  у кошик і **впав**: виявилось, що `Cart` сам пропускає видалені книги.
  Тест переписано під реальну поведінку — замовлення створюється з
  книгами, що лишились.
